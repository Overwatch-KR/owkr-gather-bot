## 처리 목적과 정보

OWKR Gather Bot은 Discord 내전 모집, 참가·대기자 관리, 티어 제출 연결,
시작 전 대기실 안내와 재시작 복구를 지원합니다.

| 정보 | 목적 |
| --- | --- |
| Discord 사용자 ID·표시 이름 | 참가·대기 구분, 티어 제출 연결 |
| 참가·취소 시각, 반응 순서와 처리 결과 | 참가 순서·중복 처리, 복구 |
| 관리자 ID, 서버·채널·메시지 ID, 내전 일정 | 내전 운영, 메시지 연결·알림 |
| 티어 메시지 원문·메시지 ID·관련 시각 | 최신 제출 저장과 작성 상태 확인 |
| 대기실 음성 채널 입장 사용자 ID | 미입장 참가자 확인 |
| 알림 상태·오류·운영 로그 | 중복 알림 방지·장애 조사·재시도 |
| 경고 대상·종류(노쇼/비매너)·기록 관리자 ID·시각·중복 방지용 요청 ID·취소 시각 | 관리자가 결정한 경고의 횟수 관리·중복 기록 방지 |
| 내전별 티어 수집 중단 정보 | 본인 삭제 요청 후 재시작·이력 조회를 통한 재수집 차단 |

티어 정보는 지정 서버·채널에서 참가자와 제출 시각 등의 조건에 따라 저장합니다.
새 제출은 해당 내전 안내에 답장해야 저장합니다. 답장 없는 새 메시지는 연결하지
않습니다. 과거 DB에 이미 연결된 메시지는 수정·삭제를 계속 처리하며, 재시작 시
채널 이력을 조회하여 답장 제출과 기존 연결 메시지의 활동을 보완합니다.
음성을 녹음하지 않습니다. 라이브러리의 메모리 캐시는 영구 저장 항목과 구분하여
최종 고지해야 합니다. 로그에는 토큰·환경 변수 전체·티어 원문을 기록하지 않도록
설계되어 있으나 사용자·메시지 식별자와 오류가 포함될 수 있습니다.

## 공개 범위와 처리 위치

참가 반응과 직접 작성한 메시지는 Discord 채널 권한에 따라 다른 이용자에게
보일 수 있습니다. 봇은 해당 채널에 참가 안내와 대상 멘션을 전송합니다.
Discord의 공개 메시지와 봇 DB의 저장 정보는 서로 다릅니다.

현재 외부 매치 서비스로 티어 정보를 자동 동기화하지 않습니다. Discord와 통신하며
운영 DB·로그·백업의 실제 처리 환경은 아래 항목을 확인한 뒤 고지해야 합니다.

- 호스팅 사업자·국가/리전: 미정
- 백업 사업자·위치·접근자: 미정
- 위탁·제공·국외 처리 관련 고지와 근거: 운영 사실에 따라 검토 필요

## 보관과 파기

내전 DB 기록은 복구에 필요한 운영 중에 보관합니다. 봇 실행 중에는 내전 시작·취소 후 약 10초
간격으로 세션과 참가·반응·티어·연결·알림·수집 중단 기록을 정리합니다. 중단 중
정리되지 못한 기록은 재시작 때 정리합니다. 오류 시 완료로 간주하지 않고 재시도합니다.

경고와 취소 이력은 서버 재적 중 기간 만료 없이 보관합니다. 경고가 있는 사용자만
봇 실행 중 정기적으로(약 1시간 간격) 재적을 조회하며 탈퇴를 확인하면 삭제합니다. 경고 조회·변경
전에도 확인하고 재가입 시각 이전의 경고는 정리합니다. 권한·통신 오류는 탈퇴로
간주하지 않습니다. 즉시 탈퇴 감지 방식이 아니므로 삭제에 지연이 있을 수 있습니다.

기존 로그·백업은 위 DB 정리로 자동 삭제되지 않습니다. 별도 보관 기한·파기 방법과
개인정보 요청 반영·복원 절차는 운영자가 확정해야 하며 현재 미완료입니다.

Discord 메시지 삭제는 전체 개인정보 삭제와 다릅니다. 시작 전 조건에 맞는 삭제
이벤트로 최신 티어 원문이 제거될 수 있지만 연결·참가·백업 전체가 지워지지는
않습니다. 시작 후에는 삭제 이벤트를 자동 처리하지 않지만 내전 DB 정리 대상이 됩니다.

## 수정·삭제 요청

서버에서 `/개인정보`를 실행하면 보관·문의 안내를 본인에게만 확인할 수 있습니다.
확인 버튼으로 본인 티어 원문과 연결 기록을 지우고 현재 참가한 내전의 티어 재수집을
중단할 수 있습니다. 참가·대기 상태는 유지되고 시작·취소 후 정리됩니다. 경고는
관리자에게 비공개로 수정·삭제를 요청하며 관리자는 `/경고`에서 취소·전체삭제합니다.

이 버튼은 Discord 원문·경고·기존 로그·백업을 지우지 않습니다. 전체 개인정보
삭제 완료로 안내하지 않습니다. 추가 요청은 위 이메일로 접수합니다. 본인 확인·완료
안내·백업 처리의 세부 절차는 [요청 안내](support.md)에 공개 전 준비 사항으로 기록했습니다.

최종 절차는 진행 중·시작 후·취소 후 요청, 백업 처리와 복원 시 삭제 반영,
재수집 방지를 포함해야 합니다.

## 보호 조치와 변경 안내

단일 프로세스·SQLite 운영, 멘션 대상 제한과 관리자 명령 검사를 사용합니다.
디스크·백업 암호화, 접근 통제와 사고 대응·통지는 실제 환경에서 확인한 뒤
반영해야 하며 확인되지 않은 조치를 적용 중인 것으로 표시하지 않습니다.

공개 전 시행일과 중요 변경의 안내 경로를 확정합니다. 한국 개인정보보호법 등
적용 법령의 필수 기재 사항·이용자 권리·미성년자 관련 의무는 실제 운영 형태에
따라 별도 검토합니다.
