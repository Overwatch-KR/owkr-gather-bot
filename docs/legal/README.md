# 개인정보·이용 안내 문서 관리

상태: **검토 중 초안** · 검토일: 2026-10-28

봇과 운영 문서를 현재 저장소에서 함께 관리한다. 정적 안내 문서만을 위해 봇을
이동하거나 별도 패키지·빌드 도구를 추가하지 않는다. 독립적으로 실행·배포하는
웹 앱이 생기면 그때 모노레포 구조를 검토한다.

봇 운영·개인정보 보호 담당은 개발자 겸 내전 총관리자 qtaghdi이며,
기본 문의 경로는 qtaghdi@gmail.com, 보조 경로는 Discord `qtaghdi`의 DM이다.
내전 DB 정리·본인 티어 삭제·관리자 경고 삭제는 구현했지만
일본 도쿄 VM 배포, Discord 읽기 전용 사전점검, 정상 종료·재부팅 복구, 백업 생성과
격리한 복사본의 복원·무결성 검사는 완료했다. 실제 10명 참가 E2E와 아래 법적 고지·
보관 결정은 별개다. 미완료 항목을 해소하기 전에는 최종 처리방침으로 표시하거나
Developer Portal의 최종 정책 URL에 등록하지 않는다. 초안은 이미 GitHub Pages에서
로그인 없이 읽을 수 있으며, 초안 게시를 이용자의 동의나 최종 정책 확정으로 보지 않는다.

## 공개 준비

- [x] 운영 담당 공개 아이디와 이메일·Discord 문의 경로 확정
- [ ] 메일 수신·회신 및 Discord DM 접근성 확인, 법정 책임자 성명·소속 등 표시 요건 확인
- [x] Oracle 일본 도쿄 VM, VM 내부 백업·운영 담당자 Mac 복사본과 관리 접속 범위 확인
- [ ] Mac 실제 보관 국가·암호화 및 제공자 계약상 수탁자·국외 이전 고지·근거 최종 확인
- [x] 내전은 운영 중만 보관하고 시작·취소 후 DB에서 정리
- [x] 경고는 재적 중 기간 만료 없이 보관, 탈퇴·재가입 확인 시 이전 재적 기록 삭제
- [x] 본인 티어 원문·연결 삭제와 해당 내전 재수집 중단, 관리자 경고 취소·전체삭제 구현
- [ ] 실제 Discord에서 권한·시각 경계·재시작·탈퇴·재가입 E2E 확인
- [x] Discord 사전점검 FAIL 0, 명령 6개 등록과 VM 재부팅 후 자동 재연결 확인
- [x] 매일 오전 6시 백업, 수동 외부 복사본 2개, 격리 복원·무결성·외래키 검사 확인
- [x] 로그 파일당 약 10MB·최대 3개, 설정·데이터 파일 권한 확인
- [ ] 로그·백업 보관 기한 확정, 요청 처리 대장과 복원 전 삭제 반영 절차 검증
- [ ] 디스크·백업 암호화와 접근 통제 확인, 사고 대응·통지 담당 확정
- [ ] 실제 처리·적용 법령에 맞게 초안 검토, 미정 표시 제거, 시행일 확정
- [x] 로그인 없이 접근 가능한 HTTPS 초안 페이지 게시와 배포 확인
- [ ] 미완료 항목 해소 후 초안 표시 제거·최종 문서 게시·시행일 확정
- [ ] Portal에 처리방침·이용약관 URL 및 지원 경로 등록, 봇 안내에서 연결

호스팅에는 승인한 공개 안내 파일만 배포한다. 저장소 전체나 상위 `docs/`를 그대로
게시하지 않는다. 설정·환경 변수·DB·백업은 배포물에 포함하지 않는다. 호스팅의 방문
로그·쿠키 등도 실제 사용 여부를 확인하여 최종 처리방침에 반영한다.

사용자가 승인한 보관 정책은 내전 시작·취소 후 정리와 서버 탈퇴까지의 경고 보관이다.
30일·180일 보관안은 채택하지 않았다. 경고 보관은 무조건적인 영구 보관을 의미하지
않으며 수정·삭제 요청, 서비스 중단과 적용 법령에 따른 처리도 마련해야 한다.

기능·수집·보관·호스팅 변경 시 같은 변경에서 문서를 갱신하고 시행일과 변경 안내를
검토한다. 문서에 약속한 처리는 코드·운영 절차와 검증으로 뒷받침해야 한다.
로그·백업·문의 메일·요청 대장의 일수 기준 보관 기한은 아직 정해지지 않았다.
이번 검토에서 DB 보관 정책을 임의로 30일·180일 등으로 바꾸거나, 실제로 없는
자동 백업 파기를 추가했다고 표시하지 않는다.
