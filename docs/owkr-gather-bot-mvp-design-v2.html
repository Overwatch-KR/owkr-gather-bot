OWKR Gather Bot 현재 구현 설계

2026-10-27 · Python 3.13 이상 · 단일 길드·단일 프로세스·SQLite 원본

현재 코드 기준의 구현 설명입니다. 과거 v2의 단일 활성 내전·자동 승격·공지 편집 명령 제안은 현재 정책에 적용하지 않습니다. 실제 서버 배포·수동 E2E 완료 여부는 별도로 확인합니다.

README · 문서 모음 · Discord E2E · 정책 공개 준비

1. 기본 흐름과 6개 명령

관리자가 내전을 만든다 → 10명이 ✅로 참가한다 → 해당 내전 티어 안내에 답장한다 → 시작 전 대기실 안내를 받는다.

명령 현재 기능 실행 범위
/내전 시간 [모드] 미리보기·시간/모드 수정 후 생성 확인 관리자·명령 채널
/티어현황 [내전] 참가·대기 인원과 티어 완료·미작성 이름 관리자·명령 채널
/내전대타 내전 대기열이 빈 모집 완료 내전의 1명 대타 모집 관리자·명령 채널
/내전취소 내전 확인 후 해당 내전만 취소 관리자·명령 채널
/경고 대상 [작업] [사유] 노쇼·비매너 조회·기록·최근 경고 취소·전체삭제 관리자·경고 채널
/개인정보 보관·문의 안내와 본인 티어 원문 삭제 운영 서버 일반 이용자

/내전상태·/공지문구는 제거했습니다. 점(.) 명령을 별도로 지원하지 않습니다. 공개 공지에는 내부 코드를 표시하지 않으며, 내전 선택 자동완성에서는 날짜·관리자·모드·코드로 구분합니다.

2. 모집·참가·일정 정책

  • 기본 정원 10명. 최초 정원까지 확정, 이후 대기입니다.
  • 시작 시각이 다른 내전은 동시 운영하고 정확히 같은 시작 시각의 새 내전은 거부합니다.
  • 반응 수신 순서와 중복을 세션별로 처리합니다. 취소 후 재신청은 새 순서입니다.
  • 한 번 정원이 찬 뒤 이탈자가 생겨도 대기자를 자동 승격하지 않습니다.
  • 참가자가 있으면 봇의 기본 ✅를 제거하고 마지막 참가자 이탈 시 다시 추가합니다.
  • 시작 시각부터 해당 내전의 반응·티어 이벤트를 자동 처리하지 않습니다.

시간은 한국 시간의 오늘 일정입니다. 오후6시20분·18:20·23시를 지원하며 지난 시각을 다음 날로 바꾸지 않습니다. 생성 후 일정 변경 명령은 제공하지 않습니다. 오프라인 중의 실제 클릭 순서를 추측해 복원하지 않습니다.

3. 대타 모집

모집 완료 공지 전송 후 대기열이 비어 있는 활성 내전에서 관리자가 명시적으로 모집합니다. 같은 내전에 열린 모집이 있으면 거부합니다. 첫 유효 ✅ 이용자를 대기열에 등록하고 본인만 멘션해 시작 전 티어 답장을 안내합니다.

대타는 자동 확정 승격되지 않습니다. 미입장자 안내는 확정 참가자 대상이므로 접수된 대타가 자동 포함되지 않습니다. 실제 명단 교체·확정의 추가 자동화는 별도 제품 결정 사항입니다.

4. 티어 제출·수정·복구

뿅뿅이#31243/챔1/챔1/챔1

배틀태그 / 탱커 / 딜러 / 힐러 순서입니다. 봇은 원문을 보관하며 형식이나 실제 티어를 검증·평가하지 않습니다.

  • 새 제출은 해당 내전의 일반 봇 안내에 답장해야 합니다. 답장 없는 새 메시지는 /·# 포함 여부와 후보 수에 관계없이 저장하지 않습니다.
  • 지정 서버·채널·확정/대기 참가자·허용 시각을 검사합니다.
  • 일반 참가자는 모집 완료 공지 전송 후부터 기본 시작 30분 전까지, 별도 접수한 대타는 접수 후 시작 전까지 수집합니다.
  • 사용자별 최신 원문 한 건과 메시지 연결을 저장합니다. 허용 기간의 수정·삭제·일괄 삭제·빈 문자열 수정을 처리하며 과거 원문으로 자동 복귀하지 않습니다.
  • 과거 DB에 이미 연결된 메시지는 답장 없이 제출했더라도 원래 내전의 수정·삭제·복구를 보존합니다.
  • 안내 메시지가 삭제되면 같은 활성 내전의 안내만 다시 만들고 관리자 채널에 알립니다.
  • 재시작 시 활성 내전의 티어 채널 이력을 보완 조회합니다. 오래된 메시지가 허용 기간에 수정된 경우도 고려합니다.
  • 미작성자 공개 멘션·전원 완료 자동 알림은 보내지 않습니다. 과거 알림은 무음 처리하는 호환 경로를 유지합니다.

5. 현황·공지·대기실

/티어현황은 모집 전에도 상태·참가·대기 인원을, 모집 완료 후에는 티어 완료·미작성 이름을 함께 보여줍니다. 응답은 본인에게만 보입니다. 활성 내전이 하나면 자동 선택하고 여러 개면 내전을 선택합니다.

모집은 Embed, 모집 완료는 일반 텍스트입니다. 문구는 운영자가 텍스트 템플릿과 티어 안내 YAML로 관리합니다. Discord 편집 화면은 없습니다. 관리자별 기본 모드·추가 안내는 유지하며 픽 제한·밴 문구 설정은 제거했습니다. 과거 설정 키는 시작을 방해하지 않습니다.

다른 활성 내전과 시작이 1시간 미만 차이면 설정된 대기실 2에 배정합니다. 배정은 DB에 저장합니다. 3개 이상 내전의 빈 방을 계산하는 기능은 아닙니다. 기본 시작 10분 전 배정 대기실에 없는 확정 참가자만 멘션합니다. 전원 입장 시 공개 안내를 생략하고 조회 실패 시 재시도합니다. 음성을 녹음·송수신하지 않습니다.

6. 관리자 경고

관리자 자격과 경고 전용 채널을 모두 검사합니다. 사유는 노쇼·비매너이며 조회·기록·취소·전체삭제를 제공합니다. 변경은 다른 관리자와 상의한 뒤 확인 버튼을 거칩니다. 봇이 실제 상의 여부나 두 번째 관리자 승인을 검증하지는 않습니다.

  • 같은 기록 요청의 재시도로 중복 가산하지 않습니다.
  • 취소는 확인창을 연 시점의 해당 사유 최근 경고를 대상으로 하고 취소 기록은 합계에서 제외합니다.
  • 재적 중 기간 만료 없이 보관하며 탈퇴 확인·관리자 전체삭제로 정리합니다.
  • 약 1시간 간격과 조회·변경 전에 대상별 REST로 재적을 확인합니다. Unknown Member만 탈퇴로 처리하고 권한·통신 오류 때는 보존합니다.
  • 재가입 시각 이전 기록도 정리하며 Guild Members Intent는 추가하지 않습니다.
  • 결과는 ephemeral이며 대상에게 멘션 알림을 보내지 않습니다. 자동 판정·제재·참가 제한은 없습니다.

7. 개인정보·담당

내전 DB는 운영 중 보관하고 봇 실행 중 시작·취소 후 약 10초 간격으로 세션·참가·반응·티어·연결·알림을 정리합니다. 재시작 때도 정리합니다. /개인정보의 확인 버튼은 본인 티어 원문·연결을 삭제하고 현재 내전 재수집을 중단하지만 참가·대기 상태는 유지합니다.

Discord 원문·경고·기존 로그·백업은 이 버튼으로 삭제되지 않습니다. 경고 요청은 관리자가 처리하며 로그·백업의 요청 반영·파기·복원은 별도 운영 절차가 필요합니다.

담당은 개발자 겸 내전 총관리자 qtaghdi, 기본 문의는 qtaghdi@gmail.com, 보조 경로는 Discord qtaghdi의 DM입니다. Oracle 일본 도쿄 배포·백업 검사 사실과 최종 정책 URL·시행일·법정 표시·보관 기한은 정책 대조 기록에서 구분합니다. 파일럿 운영 시간은 한국 시간 월~목 20:00~다음 날 02:00, 금~일 24시간이며 중지 중 정리·알림도 다음 가동까지 중단됩니다. 정책 문서는 최종 공개 전 초안입니다.

8. 구조·저장·실패 경계

생성 확인 → 모집 중 → 최초 정원 충족 → 시작 시 자동 처리 중단 → DB 정리
                 └────── 관리자 취소 ───────────────────→ DB 정리

adapters는 Discord 세부 처리, application은 운영 흐름, domain/ports는 정책·모델·계약, infrastructure는 SQLite와 저장 큐를 담당합니다. 생명주기는 coordinator, 반응은 Actor와 PersistenceWriter 순서를 유지합니다.

SQLite는 단일 프로세스로 운용하고 WAL·외래 키·트랜잭션·파일명 순서의 마이그레이션을 사용합니다. 기존 DB·메시지 연결·대타·경고 복구 방어를 보존합니다. 정상 종료 시 작업과 저장을 순서대로 마칩니다.

활성 내전·명단·공지/티어 경로·대타·알림을 복구합니다. 알림은 중복 키와 재시도를 사용하지만 Discord 전송 성공 후 DB 기록 실패 구간에서 재전송 가능성이 남습니다. 오프라인 반응 순서 손실과 티어 채널 전체 이력 조회 범위도 운영 확인 대상입니다.

9. 권한과 CI

Intents는 Guilds·Guild Messages·Guild Message Reactions·Message Content·Guild Voice States입니다. Members·Presence는 사용하지 않습니다. 티어 답장·수정·재시작 복구를 실제 서버에서 검증하기 전에는 Message Content를 끄지 않습니다.

관련 채널의 View Channel·Send Messages·Read Message History, 모집 채널의 Add Reactions·Embed Links를 사용합니다. 역할 알림은 전용 멘션 가능 역할을 권장합니다. @everyone·@here는 코드에서 차단합니다. 관리자·메시지 관리·역할 관리·추방/차단·음성 연결/말하기 권한은 요구하지 않습니다.

CI는 PR·main 변경과 수동 실행에서 Ubuntu·Python 3.13으로 아래 검사를 수행합니다. 읽기 전용 권한·pip 캐시·이전 실행 취소·10분 제한을 사용하며 자동 배포·Discord 연결을 하지 않습니다. 병합 필수 검사 지정은 저장소 규칙에서 별도로 적용합니다.

python -m pip install -e ".[test]"
python -m pytest
python -m compileall src
python -m pip check

반응 순서·동시성·중복, 시각 경계, 취소·다른 내전 분리, 재시작·멘션·탈퇴·삭제 후 재수집 차단을 자동 검사합니다. 실제 Discord E2E는 별도로 기록합니다.

10. 외부 연동 준비와 미제공 기능

실제 외부 웹 전송은 없습니다. MatchRepository·SyncSink·NoOpSyncSink와 확정 참가자 중 티어 작성자의 4필드 export는 유지합니다.

{
  "discordUserId": "123456789012345678",
  "discordDisplayName": "뿅뿅이",
  "rawTierMessage": "뿅뿅이#31243/챔1/챔1/챔1",
  "reactionOrder": 17
}

팀 편성·자동 밸런싱·실제 티어 조회, 강제 승격, 다른 날짜 예약, 과거 내전 통계, 관리자 웹 대시보드, 여러 서버·프로세스 운영은 현재 제공하지 않습니다.
