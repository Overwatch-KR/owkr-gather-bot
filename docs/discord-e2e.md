# Discord 테스트 서버 E2E

현재 `config/config.yaml`은 모집 인원 2명의 테스트 모드입니다. 테스트가 끝날 때까지 이 값을 유지하고, 운영 전 `participant_limit: 10`으로 되돌립니다.

## 1. 사전점검

봇을 중지한 상태에서 실행합니다.

```bash
source .venv/bin/activate
python -m src.e2e_preflight
```

또는 설치된 명령을 사용합니다.

```bash
owkr-gather-bot-e2e-check
```

사전점검은 Discord 데이터를 변경하지 않습니다. 다음 항목을 읽기 전용으로 확인합니다.

- 봇 토큰과 테스트 길드 연결
- Message Content Intent
- 명령·모집 공지·티어·관리자·대기실 채널 존재 여부
- 채널별 봇 최소 권한
- 관리자 역할과 모집 알림 역할
- 모집 역할의 실제 멘션 가능 여부
- 필수 슬래시 명령 6개가 테스트 길드에 등록됐는지

`FAIL`이 하나라도 있으면 종료 코드 1을 반환합니다. `WARN`은 테스트 진행은 가능하지만 운영 설정을 다시 확인해야 하는 항목입니다.

코드에서 슬래시 명령 이름을 변경한 직후에는 기존 서버 명령과 달라 실패할 수 있습니다. 이 경우 봇을 한 번 실행해 `guild application commands synced` 로그를 확인한 뒤 사전점검을 다시 실행합니다.

## 2. 봇 실행

```bash
OWKR_LOG_LEVEL=DEBUG python -m src.main
```

로그에서 다음 문구를 확인합니다.

```text
SQLite connected and migrations completed
active session recovery completed
guild application commands unchanged; sync skipped
bot ready
```

명령 구조가 변경된 최초 실행에는 `guild application commands synced`가 표시될 수 있습니다.

## 3. 2명 기준 기본 흐름

1. 관리자 역할이 있는 계정으로 `/내전`을 실행합니다.
2. **시간·모드 수정**을 눌러 기존 값이 채워지는지 확인하고 값을 수정합니다.
3. 갱신된 일정 확인창에서 **생성**을 누릅니다.
4. 생성 결과의 **모집 공지 보기** 링크가 올바른 공지로 이동하는지 확인합니다.
5. 모집 공지와 Embed, ✅ 반응을 확인하고 공개 내전 코드가 없는지 확인합니다.
6. 서로 다른 두 계정이 ✅을 누릅니다.
7. 모집 완료 공지가 한 번만 전송되고 공개 내전 코드가 없는지 확인합니다.
8. 티어 채널에 내전별 안내 메시지가 생성되는지 확인합니다.
9. 첫 사용자는 안내 메시지에 답장하고 두 번째 사용자는 답장 없이 티어를 작성합니다.
10. `/티어현황`과 `/내전상태` 상세에서 두 명 모두 작성 완료인지 확인합니다.
11. 티어 메시지를 수정한 뒤 최신 원문이 반영되는지 확인합니다.
12. 티어 메시지를 삭제해 미작성 상태로 바뀌는지 확인합니다.
13. 다시 작성한 뒤 작성 완료로 복구되는지 확인합니다.
14. 미작성자 또는 전원 완료 관련 자동 멘션이 전송되지 않는지 확인합니다.
15. `/공지문구`에서 문구 편집과 미리보기가 한 메뉴에 표시되는지 확인합니다.

## 4. 다중 내전 흐름

1. 같은 시각과 같은 모드로 내전 3개를 생성합니다.
2. `/내전상태`에서 서로 다른 코드 3개를 확인합니다.
3. 각 모집 공지에 서로 다른 계정으로 반응해 참가자가 섞이지 않는지 확인합니다.
4. 한 사용자가 같은 시각 내전 두 개에 반응해 두 번째 내전에서 충돌 대기자가 되는지 확인합니다.
5. 티어 후보가 여러 개인 사용자가 답장 없이 작성했을 때 저장되지 않고 기준 메시지 답장을 안내하는지 확인합니다.
6. 각 기준 메시지에 답장했을 때 선택한 내전에만 저장되는지 확인합니다.
7. `/내전취소`의 확인 버튼으로 하나만 취소하고 나머지 두 내전이 유지되는지 확인합니다.
8. 취소 성공 후 관리자 확인 메시지가 남지 않는지 확인합니다.
9. 공개 메시지에는 코드가 없지만 관리자 선택 목록에서는 세 내전을 구분할 수 있는지 확인합니다.

## 5. 대기실 배정과 재시작

1. 시작 시각 차이가 59분인 내전 두 개를 순서대로 생성합니다.
2. 먼저 만든 내전은 대기실 1, 나중 내전은 대기실 2로 표시되는지 확인합니다.
3. 시작 시각 차이가 정확히 1시간인 내전은 대기실 1로 배정되는지 확인합니다.
4. 대기실 안내 직전에 봇을 재시작합니다.
5. 재시작 후에도 각 내전의 배정 대기실이 유지되는지 확인합니다.
6. 배정된 대기실에 들어온 참가자는 제외되고 미입장자만 멘션되는지 확인합니다.
7. 전원이 입장한 상태에서는 공개 대기실 안내가 생성되지 않는지 확인합니다.
8. 티어 안내 메시지를 삭제해 같은 내전의 안내만 다시 생성되는지 확인합니다.
9. 재시작 후 `/내전상태`, 참가자, 티어 작성 상태와 알림 중복 여부를 확인합니다.

## 6. 테스트 종료

- 테스트용 활성 내전은 `/내전취소`로 각각 정리합니다.
- 테스트 결과에는 시각, 커밋 SHA, 사용한 계정 수와 실패 항목을 기록합니다.
- 운영 전 `participant_limit`을 10으로 되돌립니다.
- 명령 채널과 모집 공지 채널을 분리해서 운영하려면 `channels.announcement`를 공지 전용 채널 ID로 변경합니다.
